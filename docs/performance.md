# セグメント抽出の性能計測

目標: 1アプリ 10万端末で、セグメントの抽出（プレビュー、送信対象の取り出し）が数秒以内に終わること。

## 手順

```bash
./vendor/bin/sail artisan db:seed --class=PerformanceSeeder        # 10万端末・8万ユーザーを作成（約13秒）
./vendor/bin/sail artisan eevee:segments:benchmark ak_perf_benchmark_app --runs=3
```

- 端末数は `EEVEE_PERF_DEVICES=200000 ./vendor/bin/sail artisan db:seed --class=PerformanceSeeder` のように変えられる。
- データ: 端末 100,000 台（うちログインユーザーの端末 80,000 台、未ログイン 20,000 台）。属性 6 種（string / int×2 / decimal / date / bool）を JSON カラムに保存。約 10% は通知拒否、約 2% は無効トークン。

## 結果（2026-11-12 計測）

環境: MySQL 8.0.46（InnoDB, 既定設定）、PHP 8.3、4 vCPU / 16GB の開発用コンテナ。キャッシュが温まった状態で3回実行。

| 条件 | 対象端末 | 対象ユーザー | プレビュー ms（最小/最大） | ID 全件取得 ms |
|---|---:|---:|---:|---:|
| 全員 | 88,332 | 70,696 | 320 / 400 | 305 |
| 属性 eq（性別=female） | 23,438 | 23,438 | 274 / 307 | 339 |
| 属性 between（誕生月 4〜6） | 17,540 | 17,540 | 244 / 285 | 225 |
| 属性 decimal gte（累計金額≧10000） | 35,443 | 35,443 | 278 / 294 | 327 |
| 属性 date within_days（30日以内に購入） | 4,438 | 4,438 | 246 / 285 | 249 |
| 端末（iOS かつ v1.5.0 以上 かつ 7日以内にアクティブ） | 1,015 | 812 | 9 / 10 | 9 |
| 入れ子（(female AND 購入≧10) OR premium）AND カテゴリON | 19,271 | 19,271 | 261 / 265 | 304 |

- どの条件も 0.5 秒未満で、目標（数秒以内）を満たす。
- JSON 属性の条件は、そのアプリのユーザー全件を走査する（JSON_EXTRACT はインデックスを使えない）ため、件数にほぼ比例して 0.25〜0.4 秒かかる。
- 端末側の条件は `devices (app_id, last_active_at)` などのインデックスが効き、10ms 前後。
- 送信時は抽出結果を `INSERT ... SELECT` で配信ログ（push_deliveries）に書き込むため、PHP 側に全件を読み込まない（「ID 全件取得」は参考値）。

## 規模が大きくなった場合

アプリあたり 100万端末を超える、または属性の条件を多用して 1 秒を超えるようになったら、`docs/decisions.md` の D-014 にある「生成カラム＋インデックス」または「EAV テーブル」への移行を検討する。
